# ADR-0011: Default-off diagnostics and typed audit events

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

`.docs/SECURITY.md` (Logging and Audit) requires run and action identifiers,
forbids logging prompts, model responses, and secrets, and requires that log
fields be treated as untrusted. ADR-0005 forbids ANSI output. The
implementation plan (§4.5) lists the audit events and their fields, and
requires an event API that cannot accept arbitrary payload strings.

## Decision

1. Diagnostics use `tracing` with a stderr-only subscriber. It is installed
   only when `RUST_LOG` is set and never emits ANSI sequences. An invalid
   `RUST_LOG` prints one warning and leaves diagnostics off.
2. Each invocation opens a `run` span with a random `run_id`. Each discrete
   operation gets an `action_id`.
3. Audit events are built through `obs::events::AuditEvent`. All fields are
   enums, integers, static error codes, or validated tokens: entity
   identifiers must match ADR-0004, and model names must match
   `[A-Za-z0-9._:-]{1,64}`. There is no free-text field.
4. Events go to an `EventSink`. WP-1 provides a `TracingSink` and a
   `MemorySink` for tests. WP-2 adds the SQLite `events` sink, which adds
   `created_at`.
5. Secrets are wrapped in `obs::Redacted<T>`, whose `Display` and `Debug`
   both print `[REDACTED]`.
6. The panic hook prints no panic payload. With `RUST_BACKTRACE` set (and not
   `0`), it prints the location and a backtrace. A caught panic is reported
   as an internal error (exit 1).

## Consequences

- Leaking content through audit events would take a deliberate API change,
  visible in review.
- Normal runs print only command output and errors.
- Debugging a panic needs `RUST_BACKTRACE`, and the payload text is never
  shown.

## Alternatives considered

- **Diagnostics on by default at `warn`**: rejected; stderr is part of the
  user contract, and quiet output keeps it predictable.
- **A free-text `detail` field on events**: rejected; it would be the escape
  hatch the plan forbids.
- **The default panic hook**: rejected; it prints the payload, which may
  contain user data.
