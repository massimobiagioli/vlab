# ADR-0065: Live Kanban refresh and initial-based view keys

- Status: Accepted
- Date: 2026-11-17
- Supersedes: —
- Superseded by: —
- Amends: ADR-0038 (dashboards), ADR-0062 (floor/Kanban link)

## Context

The Kanban board was updated only by navigation or explicit `r`. Background
planning and worktree execution change story states while the operator is
looking at the board, so the board became stale until the user left and
re-entered the screen. The keys that open the board were also inconsistent:
Projects used `v`, while the floor used `f` to reach it. The product owner
wants the board to update in place and the shortcuts to be memorable, using the
initial letter of the destination.

## Decision

1. While the Kanban is visible, refresh it about once per second without leaving
   the screen. The refresh reuses the existing board query and
   `KanbanView::replace`, preserving the selected column/card and scroll
   offsets. Worker completion events still trigger an immediate refresh.
2. The refresh is read-only: no provider call, no write, no status reset, and no
   navigation change. It runs only for read-only views (Kanban, floor, and
   metrics) and never while the application is blocked in a form or prompt.
3. Use `k` as the Kanban shortcut on the Projects dashboard and on the floor.
   Use `f` as the Floor shortcut on the Kanban. `Esc` preserves the screen that
   opened the current view. Remove the old `v` Kanban binding so there is one
   documented shortcut.
4. Keep the existing arrow-key navigation. Because `k` is reserved for
   Kanban on Projects and the floor, use `↑` for up there; `↓` and `j` remain
   available for down. Kanban `k` remains the list-up key because the user is
   already on the board.
5. Apply the same refresh cadence to the floor and metrics read models. The
   floor tick continues to animate only while the floor is visible.
6. No schema, migration, dependency, provider contract, or trust-boundary
   change. The refresh is bounded by one query per visible read-only screen per
   interval.

## Consequences

- Story and request cards appear on the board as background work progresses,
  without a navigation detour.
- The selected card and list position stay stable across refreshes.
- A small periodic read load is added while a read-only dashboard is open.
- Projects and floor lose `k` as an up key; arrows and `j` remain, and the help
  text is updated.

## Alternatives considered

- **Refresh only on worker events**: rejected; the worker does not emit an event
  for every internal story transition.
- **Refresh on every keypress**: rejected; it does not help an idle viewer and
  adds unnecessary reads.
- **Keep `v` and add `k`**: rejected; two shortcuts for one destination repeats
  the inconsistency.
- **Use `K`/`F` uppercase**: rejected; the product owner asked for the initial
  letter and the lowercase keys are easier to discover.
