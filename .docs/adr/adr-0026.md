# ADR-0026: Bounded synchronous provider port and planning contract

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —
- Amended by: ADR-0030 (credential source only)
- Amended by: ADR-0048 (workflow calls and interaction kind)

## Context

WP-5 introduces the only outbound model integration. The plan describes an
asynchronous provider port, but the application is a one-shot CLI whose
database adapter already owns a current-thread runtime. A synchronous bounded
port keeps the planning state machine, retry policy, and tests deterministic
without nesting runtimes. The security and behavior requirements (timeouts,
size caps, strict output validation, cancellation) do not depend on the async
signature.

## Decision

1. **Port.** `domain::provider::ModelProvider` exposes one synchronous
   `complete(&ProviderRequest) -> Result<ProviderResponse, ProviderError>`.
   No HTTP type appears in the domain signature or `Debug` output.
2. **Adapter.** `infra::provider::deepseek::DeepSeekProvider` uses
   `reqwest::blocking` with rustls, certificate validation, no redirects,
   connect/attempt timeouts, a 256 KiB response cap, and `DEEPSEEK_API_KEY`
   only in the authorization header. Errors carry status/request identifiers,
   never response bodies.
3. **Determinism.** `ScriptedProvider` records exact requests and returns
   queued outcomes; `TestClock` records retry sleeps instead of waiting.
4. **Retry.** Only rate-limit, timeout, transport, and 5xx failures are
   retried; at most two retries. `Retry-After` takes precedence. Every attempt
   consumes the budget and emits a `provider_attempt` event without content.
5. **Structured output.** Planning output is JSON schema version 1, parsed with
   unknown fields rejected. Questions and stories are mutually exclusive;
   stories are bounded; due dates are computed locally in UTC from complexity
   (`small=2`, `medium=5`, `large=10` days). The model cannot supply a date.
6. **Persistence and cancellation.** The request is inserted as `TODO`, marked
   `PLANNING`, then stories/questions/status are committed in one transaction.
   A stale `PLANNING` lease is recovered as `FAILED stale_planning`. Cancellation
   stops further attempts, marks the request `FAILED cancelled`, and reports
   that remote processing may have continued.
7. **Dependencies.** Add `reqwest` 0.13.5 (blocking, json, rustls),
   `serde_json` 1.0.154, `time` 0.3.55, and `ctrlc` 3.5.2; `wiremock` 0.6.5 is
   a development dependency. Record them in `DEPENDENCIES.md`.

## Consequences

- Planning is a bounded, testable state machine with no live model in CI.
- Provider calls block the CLI process for at most the attempt deadline; the
  total deadline and retry cap bound the operation.
- The synchronous port is simpler than an async trait, but a future concurrent
  client would need a new decision and adapter work.
- The vendored SQLx patch remains in place for the bundled SQLite engine.
- Output is strict; malformed model results are a validation failure with no
  repair or retry.

## Alternatives considered

- **Async trait with boxed futures**: rejected for this one-shot CLI; it adds
  runtime nesting and mock complexity without changing security properties.
- **`reqwest::blocking` with default TLS**: rejected; the rustls/no-default
  configuration keeps the dependency surface and certificate behavior explicit.
- **Accept model-supplied due dates**: rejected; dates are local policy and a
  trust boundary.
- **Repair loop for invalid output**: rejected; it multiplies provider cost and
  hides validation failures.
- **Retry all failures**: rejected; authentication, validation, and cancelled
  outcomes are not safely retryable.
