# ADR-0029: Activate hosted CI before the release tag

- Status: Accepted
- Date: 2026-11-12
- Supersedes: ADR-0013
- Superseded by: —

## Context

ADR-0013 deferred hosted CI until Go-Live because the repository had no remote
and WP-1 to WP-6 were delivered as uninterrupted local work. The repository now
has a GitHub remote, the complete deterministic implementation has been pushed,
and the product owner asked to activate CI to verify the build on Linux and
macOS. The reviewed workflow and Dependabot files were already committed,
fully commented, with exact activation instructions.

## Decision

1. Restore `.github/workflows/ci.yml`, `.github/workflows/security.yml`, and
   `.github/dependabot.yml` by removing the disabled header and the leading
   comment marker, exactly as described in [`../CI.md`](../CI.md).
2. Keep the workflow content as reviewed: read-only token, pinned action SHAs,
   `persist-credentials: false`, Linux+macOS fmt/clippy/test, Linux audit/deny,
   daily advisory scan, weekly Dependabot updates.
3. Keep `make check` mandatory locally; hosted CI supplements, and does not
   replace, local gate evidence.
4. Manual repository settings (branch protection, required checks, Dependabot
   alerts, private vulnerability reporting) remain required before the release
   gate, because they are not repository files. This ADR activates the
   workflows; it does not complete the release gate.

## Consequences

- Every push and pull request now gets Linux and macOS verification, so the
  bundled SQLite/reqwest build and platform-specific tests are checked.
- A failing hosted run is visible and must be fixed before merge/release.
- CI consumes hosted minutes and needs network access to crates.io and the
  advisory database; failures there are investigated, not waived.
- Branch protection is still manual; until it is configured, a direct push can
  bypass required checks.
- The daily scan may surface new advisories between changes; the normal
  remediation and ADR process applies.

## Alternatives considered

- **Keep CI disabled until the tag**: rejected by the product owner; early
  hosted feedback is wanted now.
- **Enable only Linux**: rejected; macOS is the primary local platform and the
  workflow matrix already covers both.
- **Rely on local gates only**: rejected; local runs do not exercise the Linux
  toolchain or fresh CI environments.
- **Rewrite the workflow**: rejected; the reviewed configuration is unchanged.
