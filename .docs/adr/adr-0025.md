# ADR-0025: Optional project GitHub source with a global GitHub credential

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —
- Amended by: ADR-0030 (credential source only)

## Context

The product owner requires projects to carry a **github source** and requires a
GitHub key to operate on a project. The key must also exist at the general
level. The source-control provider is `github` for now, as a separate role
from the DeepSeek planning provider. No GitHub operation is specified yet;
adding network behavior without a concrete operation would widen the trust
boundary and the dependency surface prematurely.

The product owner confirmed on 2026-11-12: an optional full URL
`https://github.com/owner/repo`, a single global `GITHUB_API_KEY`, a separate
source-control provider configuration, and configuration/validation only for
now.

## Decision

1. **Project field.** `projects.github_source` is an optional canonical URL
   `https://github.com/<owner>/<repository>`. Parsing is strict: HTTPS GitHub
   only, exactly two path segments, allowed owner/repository characters,
   optional trailing slash and `.git` stripped, no query or fragment. Invalid
   input exits 2 before storage.
2. **Credential.** The GitHub API key is read only from `GITHUB_API_KEY`, is
   never stored in `settings.yaml`, the database, logs, errors, prompts, or
   command output, and is never displayed; only `set`/`unset` is reported.
3. **Source-control provider.** `settings.yaml` gains an optional
   `source_control` section with `provider: github`. GitHub is the only
   supported value; omitting the section defaults to GitHub. The existing
   `provider`/`model` fields continue to configure DeepSeek for planning.
4. **Project creation.** `--new-project <name> --github-source <url>` validates
   the URL, requires a valid settings document, verifies that the source-control
   provider is GitHub, and requires `GITHUB_API_KEY` presence. It then persists
   the project atomically; no network call is made.
5. **Display.** `--new-project` echoes the canonical source, `--list-projects`
   shows it, and `--show-project-kanban` displays it when present.
6. **Migration.** Schema v4 adds the nullable `github_source` column. Existing
   projects migrate with `NULL`. The migration is forward-only and preserves
   all earlier data.
7. **Scope of operations.** This decision implements configuration and local
   validation only. A future GitHub operation (for example repository access,
   issue synchronization, or commit/push) requires a new ADR defining the
   exact operation, permission scope, network bounds, and failure handling.
8. **No per-project secret.** There is no project-level key. Sharing one
   environment credential avoids storing secrets next to project data and
   keeps rotation in the environment.

## Consequences

- Projects can declare their repository without coupling planning to GitHub.
- The GitHub key can be rotated without editing project rows.
- The source URL is not a secret and is retained as project metadata; the key
  is not.
- A missing key blocks only the creation of a GitHub-backed project, not local
  projects or the rest of the CLI.
- The source-control provider is explicitly separated from the AI provider, so
  future providers do not overload `provider`/`model`.
- No GitHub API call, PAT scope, rate limit, or network retry exists yet; this
  is documented as a limitation and deferred to a concrete operation.

## Alternatives considered

- **Required GitHub source**: rejected; local projects without a repository
  remain useful and the product owner selected optional.
- **Store a key per project**: rejected; it would create a secret column,
  require encryption/key management, and conflict with the no-secrets rule.
- **Reuse the DeepSeek `provider` field for GitHub**: rejected; one field
  cannot represent two independent providers.
- **Free-form repository string**: rejected; strict URL validation prevents
  ambiguous ownership and display issues.
- **Implement GitHub API access now**: rejected; no operation or permission
  scope is defined, and a network path needs its own security and test design.
