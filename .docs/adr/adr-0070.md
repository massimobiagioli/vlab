# ADR-0070: Integrate DONE stories into develop and materialize a testable sandbox

- Status: Accepted
- Date: 2026-11-17
- Supersedes: —
- Superseded by: —
- Amends: ADR-0032 (clone-only workspace), ADR-0050 (bounded execution and
  no automatic merge), ADR-0009 (flag-based actions), ADR-0014 (repository-local
  data)

## Context

VLab executes each story in an isolated worktree and leaves the commit on
`vlab/<story-id>`. Nothing integrates those commits into a shared branch, and
there is no single local checkout that a person can open to try the current
state of a project.

The product owner requires two related capabilities:

1. Every card that reaches `DONE` must be integrated into a `develop` branch and
   pushed to the project's remote. `develop` must be created when it does not
   exist.
2. A repository-local `.sandbox/` directory must contain a testable checkout of
   `develop` for every project of the active laboratory, refreshed at startup
   and after each DONE card.

ADR-0032 deliberately authorized only `git clone`; push and branch operations
were deferred. ADR-0050 and `AGENTS.md` state that VLab never merges
automatically. This decision changes those two rules in a bounded way: VLab may
merge a reviewed story commit into `develop` and push only that branch. It never
merges into the default branch, never force-pushes, and never deploys.

## Decision

1. **Integration target.** After a story reaches `DONE` with a non-empty branch
   and commit, VLab integrates that commit into the project's `develop` branch
   with a `--no-ff` merge. `develop` is created from `origin/develop` when it
   exists, otherwise from the remote default branch, otherwise from the base
   checkout `HEAD`. A card with no commit is skipped and recorded.
2. **Push.** When the base checkout has an `origin` remote, VLab pushes
   `refs/heads/develop` to `origin` without force. A successful push or a
   project without a remote marks the integration complete. A failed push does
   not change the card state: the local merge is kept, a content-free failure
   event is recorded, and the push is retried on the next startup or explicit
   sync.
3. **Idempotence and retry.** Integration checks whether the story commit is
   already an ancestor of `develop`. Repeated passes therefore never create a
   duplicate merge, and a retry after a push failure only retries the push.
   Integration state is stored on `story_outcomes`:
   `integrated_at`, `push_ok`, and `integration_error` (schema v18).
4. **Conflicts.** A conflicting merge is aborted in the temporary integration
   worktree, the card remains `DONE`, a `develop_conflict` event is recorded,
   and the next pass retries. VLab never resolves a conflict with a heuristic
   and never force-pushes over it.
5. **Sandbox.** `.sandbox/<project-id>` (or `<data-dir>/sandbox/<project-id>` for
   non-repository layouts) holds a disposable clone of the project's `develop`
   branch. The sandbox is refreshed:
   - at interactive startup;
   - after each DONE card;
   - with the hidden `--sync-sandbox` action.
   The refresh fetches the base checkout's `origin/develop` when possible,
   fast-forwards `develop` when it is strictly behind, then resets the sandbox
   to `develop` and removes untracked files. Local sandbox edits are discarded
   by design.
6. **Scope of projects.** All projects of the active laboratory with a GitHub or
   folder source are included. Projects without a source are skipped. Folder
   projects use their local `develop` and have no remote push.
7. **Trust boundary.** Push credentials use the existing private askpass
   mechanism: the token travels only in the child environment, never in
   arguments, URLs, logs, errors, or sandbox files. Network operations are
   bounded by a timeout and discard git output. `credential.helper` is disabled.
   No force push, no default-branch merge, no submodule or LFS operation.
8. **Events and observability.** Content-free `develop_integrated`,
   `develop_push_failed`, `develop_integration_failed`, `sandbox_synced`, and
   `sandbox_sync_failed` events carry only the story or project identifier and
   an error code. File lists, diffs, URLs, and git output are never recorded.
9. **Paths and configuration.** `.sandbox/` is ignored by git and created at
   runtime as a private directory (`0700`), mirroring `.workspace`. It is not
   tracked: a checkout cannot carry a private directory mode, so a tracked
   skeleton would fail the fail-closed permission check. `Paths::sandbox_dir()`
   derives it from the data directory, so debug builds use the repository root
   and installed builds use the data directory.
10. **No retroactive publication.** Outcomes that already existed when this
    decision was deployed are marked `legacy_not_integrated` and are not merged
    or pushed automatically. They may be partial, rejected, or contain
    historical credential files. Only cards that reach `DONE` after this
    decision are integrated automatically; a manual reset of the integration
    columns can explicitly retry a legacy card.

## Consequences

- `develop` becomes the single testable integration branch; `main` remains
  untouched and no automatic merge reaches it.
- A DONE card is not blocked by a network failure, and a failed push remains
  visible and retryable.
- `.sandbox/` can be deleted at any time; it is a disposable projection of
  `develop`.
- The base checkout gains a `develop` branch and temporary worktrees under
  `.workspace/.integrate/`; these are local and ignored.
- A conflict or a remote that rejects the push needs a human to resolve or fix
  credentials; VLab records the failure instead of hiding it.
- Historical DONE cards are not published retroactively; they stay as they are
  and are marked `legacy_not_integrated`, so old partial work or credential
  files are not pushed to `develop` by an upgrade.
- The token is exposed to the `git` child environment for fetch/push, the same
  trust level as cloning (ADR-0032).

## Alternatives considered

- **No push, only a local branch**: rejected; the product owner requires the
  remote `develop` to be updated.
- **Push the `vlab/<story>` branch only**: rejected; it does not produce a
  shared testable branch.
- **Force-push or auto-resolve conflicts**: rejected; it can destroy remote
  work and violates the security baseline.
- **Merge into `main`**: rejected; the default branch is release-controlled and
  remains out of scope.
- **Make `.sandbox` a worktree of the base checkout**: rejected; a branch cannot
  be checked out in two worktrees and integration would need extra
  synchronization. An independent clone keeps the sandbox disposable.
- **Repair integration inside the provider loop**: rejected; integration is
  deterministic local git work and does not need the model.
- **Unbounded retries on startup**: rejected; integration is idempotent and one
  bounded attempt per pass is enough.
