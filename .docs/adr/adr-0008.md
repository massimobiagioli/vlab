# ADR-0008: Pinned toolchain and incremental dependency baseline

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

`STACK.md` requires a pinned, supported toolchain, verified dependencies, only
the features that are needed, and a committed lockfile. WP-1-T2 of the
implementation plan lists every crate the whole release will need. Adding
crates that WP-1 does not use would widen the audit and license surface
without benefit, against the simplicity rule of `CONSTITUTION.md` and the
"enable only required" rule of `STACK.md`. The YAML parser needs an explicit
choice, because several popular options are deprecated or unmaintained.

## Decision

1. Pin Rust 1.99.1 (current stable on 2026-11-12) with `clippy` and `rustfmt`
   in `rust-toolchain.toml`. Use edition 2024 and `rust-version = "1.99"`.
2. Add a dependency only in the work package that first uses it, after fresh
   verification against crates.io, RustSec, license, and maintenance activity.
   Record it in `.docs/DEPENDENCIES.md`.
3. WP-1 adds only `clap`, `directories`, `thiserror`, `tracing`,
   `tracing-subscriber`, and `uuid`, plus the development dependencies
   `assert_cmd` and `tempfile`, with default features disabled where they
   would add unused capability (`clap` without `color`, `tracing-subscriber`
   without `ansi`).
4. Use `serde-saphyr` for YAML settings in WP-2. Reject `serde_yaml`
   (deprecated), `serde_yml` (RUSTSEC-2025-0068), and the `serde_yaml` forks
   built on `unsafe-libyaml` or its forks.
5. Forbid `unsafe` code in every target through `[lints.rust]` and the crate
   attribute. Deny `unwrap` and `expect` in production code; tests may use
   them.
6. Commit `Cargo.lock`; CI builds with `--locked`.

## Consequences

- The dependency tree stays small, and each package's review sees only the
  crates it introduces.
- WP-1-T2's list is delivered over several packages instead of at once; the
  deferred selections and their first use are listed in
  `.docs/DEPENDENCIES.md`.
- The toolchain pin must be raised deliberately; Dependabot does not update
  `rust-toolchain.toml`.

## Alternatives considered

- **Add every planned crate in WP-1**, as the plan suggests: rejected; unused
  dependencies add risk without value, and their verification would be stale
  by the time they are used.
- **Track the `stable` channel without a pin**: rejected by `STACK.md`
  (reproducible, verified builds).
- **`serde_yaml` or a fork built on `unsafe-libyaml`**: rejected for the
  advisories and maintenance status above.
- **TOML instead of YAML**: rejected; the specification fixes
  `settings.yaml`.
