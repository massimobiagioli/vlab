# ADR-0032: Clone GitHub projects into .workspace

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —
- Amends: ADR-0025 (clone operation only)

## Context

ADR-0025 made the project GitHub source configuration-only and explicitly
deferred network operations. The product owner now requires a project created
with `--github-source` to have a local checkout under `.workspace/`, outside
version control. The checkout is needed before planning can reason about a
real codebase.

`git worktree` is not a clone primitive: it adds a working tree to an existing
local repository. The initial need is one independent checkout per project, so
a plain `git clone` is the smallest operation that satisfies it. A shared bare
mirror plus worktrees would only pay off when several projects or branches
share one repository; it adds cache invalidation, locking, and cleanup rules
that are not justified yet.

The operation crosses a new trust boundary: it executes the local `git`
binary, reads a credential from the private settings file, and receives data
from GitHub. The token must never appear in process arguments, URLs, logs,
errors, or command output.

## Decision

1. **When.** `--new-project <name> --github-source <url>` validates the URL,
   settings, and GitHub credential, then clones the repository before the
   project row is committed. If the clone fails, no project row is created.
   Projects without `--github-source` are not cloned.
2. **Where.** The checkout is `<workspace-root>/<project-id>`, where the root is
   `<repo>/.workspace` for the repository-local debug layout and
   `<data-dir>/workspace` otherwise. `.workspace/` is ignored by git. The
   project row stores no local path; the path is derived from the project ID.
3. **Primitive.** Run `git clone` without a shell, with an explicit `--`
   separator, and with the destination fixed by VLab. Full history is cloned;
   shallow and partial clones are deferred until a requirement exists.
4. **Credential.** The GitHub token comes from
   `credentials.github_api_key`. VLab creates a private, short-lived askpass
   script (mode `0700`) and passes the token only through the child process
   environment (`VLAB_GIT_TOKEN`). It sets `GIT_ASKPASS`,
   `GIT_ASKPASS_REQUIRE=force`, and `GIT_TERMINAL_PROMPT=0`, disables
   credential helpers, and never builds a URL containing the token. The script
   is removed on every path.
5. **Atomicity.** Clone into a private temporary directory under the workspace
   root, then rename the checkout to the final project directory. On failure,
   remove the temporary directory. If the database insert fails after a
   successful clone, remove the checkout. An existing final directory is a
   precondition error and is never overwritten.
6. **Bounds and errors.** A clone is bounded by a 300-second timeout and its
   output is discarded, never echoed. Missing `git` is a configuration error;
   timeout and failed clone are workspace failures with an actionable hint.
   Raw git output is not propagated.
7. **Tests.** Deterministic tests use a fake `git` executable for CLI behavior
   and a local `file://` repository for the infrastructure adapter. No test
   requires GitHub or network access.
8. **Scope.** This decision authorizes only the clone operation. Fetch, pull,
   push, branch operations, submodules, LFS, and GitHub API calls remain out of
   scope until separately specified.

## Consequences

- A GitHub-backed project has a local checkout immediately after creation.
- The workspace can be large and is not backed up or encrypted by VLab; it is
  disposable and ignored by git.
- The token is exposed to the `git` child process environment, which is
  readable by the same operating-system user. This is the same trust level as
  the private settings file.
- Clone failures are atomic with respect to project rows, so a retry can use
  the same command.
- A process kill can leave a temporary directory; a later attempt cleans only
  its own temporary directory. `make clean-workspace` is the explicit reset.
- A future shared-repository or multi-worktree requirement needs a new ADR.

## Alternatives considered

- **`git worktree` immediately**: rejected; it requires a bare mirror and
  solves a multi-checkout problem that does not exist yet.
- **Clone with the token in the URL or arguments**: rejected; process listings
  and shell history can expose it.
- **Use the system credential helper**: rejected for the default path; it
  writes or caches credentials outside the settings file and behaves
  differently per machine.
- **Clone after inserting the project row**: rejected; a failed clone would
  leave a row without a checkout and no retry command.
- **Shallow clone**: deferred; it changes history and worktree behavior and is
  not required for the initial operation.
- **A Rust git library**: deferred; it adds a large dependency and TLS surface
  when the local `git` binary already provides the required operation.
