# ADR-0063: Maintain the Tech Lead skill after every feature

- Status: Accepted
- Date: 2026-11-17
- Supersedes: —
- Superseded by: —
- Amends: ADR-0007 (tracked agent guidance), ADR-0037 (tracked feature plans)

## Context

The `vlab-tech-lead` skill is the operational entry point for planning and
reviewing a feature. It is only useful if it reflects the current architecture,
commands, invariants, and lessons. A skill that drifts from `.docs/`, the ADR
registry, and the code becomes a source of stale instructions, which is worse
than having no skill.

The product owner requires the Tech Lead skill to be updated after every
implemented feature, not only when someone remembers.

## Decision

1. Every implemented feature updates
   `.agents/skills/vlab-tech-lead/SKILL.md` in the same change.
2. The update covers, when affected: the project map, invariants, commands,
   screens, routing table, references, review checklist, and anti-patterns.
   It records a lesson only when the lesson changes how the next feature should
   be approached.
3. The skill stays operational and current. Stale guidance is removed; the file
   is not a changelog and does not duplicate the full specification.
4. `AGENTS.md` states the maintenance rule, and the feature plan includes it as
   a checklist item where relevant.
5. The skill is guidance, not a source of product rules. If it conflicts with
   `.docs/` or an accepted ADR, the documents win and the skill is corrected.

## Consequences

- The next feature starts from a current operational playbook.
- Each feature has one small documentation obligation in addition to the ADR
  and feature plan.
- The skill can be reviewed with the code and documentation in the same diff.

## Alternatives considered

- **Update only when the workflow changes**: rejected; small changes to
  commands, screens, and invariants are exactly what makes the skill stale.
- **Generate the skill from `.docs/`**: rejected; the skill is a procedure and
  routing layer, not a mechanical copy of the specification.
- **Keep a changelog in the skill**: rejected; it would grow without improving
  the next decision.
