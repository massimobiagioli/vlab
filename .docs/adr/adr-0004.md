# ADR-0004: Short hexadecimal entity identifiers

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

Every persistent entity needs an identifier that is unique, stable, easy to
type in a terminal, and safe to pass as a command argument. The specification
asks for a short UUID-style identifier suitable for terminal use and requires
collision checks before persistence. Identifiers must never be interpreted as
filesystem paths.

## Decision

1. Generate entity identifiers from a UUIDv4 and keep the first eight lowercase
   hexadecimal characters (for example `a3f91c07`).
2. Store the short value as the primary key. Uniqueness is enforced by the
   database; generation retries a bounded number of times on collision and then
   returns a typed internal error.
3. Validate identifiers against `^[0-9a-f]{8}$` before any database query.
   Malformed identifiers produce a usage error; well-formed but absent
   identifiers produce a not-found error.
4. Use typed newtypes for each entity (`LabId`, `AgentId`, `ProjectId`,
   `RequestId`, `StoryId`) so identifiers cannot be passed to the wrong
   repository by accident.
5. Display identifiers exactly as stored. Do not introduce prefix resolution or
   aliases.
6. Never use an identifier directly as a path, filename, or shell fragment.

## Consequences

### Positive

- Short, copyable identifiers improve terminal usability.
- Typed newtypes prevent a class of cross-entity mistakes.
- Validation is deterministic and cheap.

### Negative / trade-offs

- The 32-bit value space can collide at large scale; the bounded retry handles
  the practical case, and the primary key remains the final authority.
- Identifiers are not sortable by creation time.
- Full UUIDs are not recoverable from the short identifier.

## Alternatives considered

- **Full UUIDs**: rejected as verbose for interactive use.
- **UUIDv7 / ULID**: provides time ordering but longer values; not needed for
  the initial scope.
- **Sequential integers**: rejected because they leak volume and are easier to
  guess; not UUID-style.
- **Prefix resolution**: rejected as ambiguous and unnecessary when the full
  short value is displayed.
