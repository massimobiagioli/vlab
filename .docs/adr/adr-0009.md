# ADR-0009: Flag-based command surface with one primary action

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —
- Amended by: ADR-0033 (project command operands only)
- Amended by: ADR-0038 (subcommand surface)

## Context

Specification §4.1 defines the commands as long flags in four help groups,
requires exactly one primary action per invocation, and allows `--to-agent`
only with `--ask`. Assumption A-08 of the implementation plan adds a `--yes`
modifier so that destructive commands can run without a terminal. The plan
also requires `--version`, help on a bare invocation, and scaffold handlers
until each command is implemented. `.docs/SECURITY.md` and `STACK.md` require
stable exit codes, strict stream separation, and no ANSI output.

## Decision

1. Every primary action is a long flag in one clap argument group that
   accepts at most one member. The help groups are, in order, Settings,
   Laboratories, Projects, and Agents, as in §4.1. `--help`, `--version`, and
   `--yes` appear under Options.
2. `--new-request <project-id> [request-text]` takes one or two values. A
   third value is a usage error.
3. Modifiers are validated in application code after parsing, not with clap
   `requires`: clap skips a `requires` rule whose target conflicts with an
   argument already present, so `--list-labs --to-agent X` would pass.
   `--to-agent` is valid only with `--ask`. `--yes` is valid only with
   `--delete-lab`, `--delete-project`, or `--delete-agent`.
4. A bare `vlab` prints the same help as `--help` to stdout and exits 0
   without touching the filesystem. `--version` prints `vlab <version>`.
5. Parse errors exit 2 and use the shared two-line `Error:`/`Hint:` contract.
   clap's problem statement, including indented detail lines, is kept and
   sanitized; its usage block and tips are dropped.
6. clap is built without its `color` feature, so help and errors contain no
   ANSI sequences.
7. Until a later package implements it, each action returns
   `AppError::NotImplemented` (exit 1, "`<flag>` is not available in this
   build."). The variant is removed by WP-6.
8. Exit codes follow specification §14: 0 success, 1 operation or provider
   failure, 2 invalid input or configuration, 3 missing entity or active
   context, 4 validation or precondition failure (including confirmation
   required without a terminal), 5 cancellation, 130 interruption.

## Consequences

- The flag surface is frozen before domain work; later packages implement
  handlers without renaming flags.
- `--yes` exists before its confirmation flow (WP-4). A-08 is still a
  blocking assumption before WP-4; if the product owner rejects it, this ADR
  is superseded and the flag removed.
- Tests snapshot the help output (`tests/snapshots/help.txt`), so any help
  change is an explicit, reviewed diff.

## Alternatives considered

- **Subcommands (`vlab lab new`)**: rejected; the specification fixes the
  flag syntax.
- **clap `requires` for modifiers**: rejected for the conflict-skipping
  behavior described above.
- **Printing clap's native error format**: rejected; it differs from the
  `Error:`/`Hint:` contract and includes a usage block.
- **No `--yes`; deletion only from a terminal**: kept open as the outcome if
  A-08 is rejected.
