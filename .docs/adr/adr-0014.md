# ADR-0014: Makefile task runner and project-local development data

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —
- Amended by: ADR-0030 (tracked settings example only)

## Context

The product owner wants one entry point for everyday developer tasks
(building, testing, linting, running the gates). They also want the
configuration and database produced while developing to stay in a `.data/`
folder inside the project, outside version control. ADR-0002 and `STACK.md`
require the installed application to use per-user directories and never to
write to the current working directory implicitly. ADR-0010 allows absolute
`VLAB_CONFIG_DIR` and `VLAB_DATA_DIR` overrides for tests and controlled
deployments.

## Decision

1. A root `Makefile` wraps the Cargo commands. `help` is the default target
   and lists every target with a one-line description. The targets are
   `build-debug`, `build-release`, `run`, `test`, `lint`, `fmt`, `fmt-check`,
   `clippy`, `audit`, `deny`, `check` (every gate in `AGENTS.md` §7),
   `tools`, `snapshot`, `clean`, and `clean-data`.
2. `make run` sets `VLAB_CONFIG_DIR` and `VLAB_DATA_DIR` to the absolute
   path of `<project>/.data`, so `settings.yaml` and `vlab.db` are written
   there. Before running, it creates `.data/` if needed and sets its mode to
   `0700`. `.data/` is ignored by git.
3. The binary's defaults do not change. Outside `make run`, VLab still uses
   per-user directories (ADR-0002, ADR-0010).
4. The Makefile finds `cargo` on `PATH` or in `~/.cargo/bin`, uses POSIX
   `sh`, and works with the `make` shipped with macOS.
5. The Makefile adds no rules of its own: each target runs the same command
   that `AGENTS.md` or `.docs/CI.md` documents.

## Consequences

- Contributors and the product owner use the same commands, and
  `make check` is the single local gate before Go-Live (ADR-0013).
- Development data is easy to inspect and to reset (`make clean-data`), and
  never mixes with a real per-user installation.
- `make run` changes the mode of an existing `.data/` to `0700`. The binary
  itself never changes the mode of an existing directory (ADR-0010).

## Alternatives considered

- **Make `.data/` the binary's default location**: rejected; it conflicts
  with ADR-0002 and `STACK.md`. If the product owner wants this for the
  product, it needs a new ADR that supersedes ADR-0002, and a change to
  `STACK.md`.
- **`just` or `cargo-make`**: rejected; each adds a tool to install, while
  `make` is already available on macOS and Linux.
- **Shell scripts in `scripts/`**: rejected; there would be no built-in
  listing of tasks, and they would be harder to discover than `make help`.
