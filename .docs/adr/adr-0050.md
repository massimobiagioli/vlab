# ADR-0050: Real bounded agent execution in project git worktrees

- Status: Accepted
- Date: 2026-11-13
- Supersedes: ADR-0048 (bounded no-tool simulation)
- Amends: ADR-0003 (tools), ADR-0026 (provider contract), ADR-0032
  (workspace), ADR-0043 (Kanban detail), ADR-0049 (startup resume)
- Amends: `AGENTS.md` §6 and `TECHNICAL-SPECIFICATIONS.md` §2 (execution scope)

## Context

ADR-0048 completed stories with a textual work/review simulation. A card that
declared `Playbook.md` written was `DONE` while no file existed in
`.workspace/<project-id>`. The product owner rejects simulation: a story must be
worked for real inside the project checkout, using git worktrees, and the
outcome must be stored in SQLite.

VLab already clones an optional GitHub source into `.workspace/<project-id>`
(ADR-0032). The new capability is to let the assigned agent read and write that
checkout, run commands, and commit on a dedicated branch. This is a deliberate
security-scope change: the model now has real tools and can affect files and
processes. It must remain bounded, local, and confined to a worktree.

## Decision

1. **Worktree per story.** Before working, the application creates
   `.workspace/.worktrees/<story-id>` from the project clone with
   `git worktree add -b vlab/<story-id> <path> HEAD`. A stale worktree and
   branch with the same name are removed first, best effort. Stories without a
   cloned project cannot be executed.
2. **Application-owned loop.** The assigned agent works through a bounded
   action loop. Each round is one provider call with the story, the previous
   observations, and a strict JSON action schema. The model proposes up to four
   actions per round; the application validates and executes them. The loop
   ends when the model returns `done: true` with a summary, when the round
   bound is reached, on cancellation, or on a tool error that cannot continue.
3. **Tools.** `list_files` (bounded listing), `read_file` (≤ 64 KiB),
   `write_file` (creates or replaces a file, ≤ 128 KiB), and `run_command`
   (`sh -c`, 60-second timeout, 64 KiB captured output). Every path is resolved
   inside the worktree; absolute paths, `..`, and symlink escapes are rejected.
   Commands run with the worktree as working directory, a minimal environment
   (`PATH`, `HOME` set to a private temporary directory), no shell profile, and
   no inherited secret environment variables.
4. **Bounds.** At most 12 work rounds, one provider call per round, 120-second
   call timeout, 2,048 output tokens, four actions per round, and a 15-minute
   work deadline. The review is one additional call. The existing retry policy
   is not applied to tool rounds: a failed call ends the attempt.
5. **Commit.** When the loop ends successfully, the application stages all
   changes and commits them on the story branch with a fixed author
   (`VLab <vlab@localhost>`). The commit hash is recorded. A story with no
   changes is not committed: the attempt fails without storing an outcome.
6. **Attempts.** Schema v10 adds `stories.execution_attempts`. Each execution
   increments it. After three failed attempts the story becomes `BLOCKED` and a
   content-free `workflow_failed` event with code `workflow_attempts_exhausted`
   is recorded. Successful execution resets nothing; the outcome row is the
   record of completion.
7. **Review.** The reviewer is the first active QA in the project roster, or in
   the laboratory roster when the project roster is empty; if there is no QA,
   the Tech Lead reviews. The review call receives the work summary, the
   changed-file list, and a bounded diff, and returns one `review_outcome`
   string. The review is recorded and advisory: the committed work is not
   discarded automatically.
8. **Outcome.** Schema v10 also adds `branch`, `worktree_path`, and
   `commit_sha` to `story_outcomes`. The row stores the work summary, review
   text, reviewer, branch, worktree path relative to `.workspace`, commit, and
   completion time. `DONE` means the agent executed in a worktree, the changes
   were committed, and the review was recorded.
9. **Startup resume.** The automatic resume from ADR-0049 keeps working: at
   startup, pending assigned `TODO`/`IN_PROGRESS`/`IN_REVIEW` stories with no
   outcome are executed; an assigned `TODO` story moves to `IN_PROGRESS` when
   the attempt starts. The three-attempt bound prevents infinite paid retries.
10. **Events.** Content-free events cover work started/completed, review,
    artifact/commit, failure, and attempt exhaustion. Prompts, file content,
    command output, diffs, and summaries are project data, never event content.

## Consequences

- A `DONE` card now corresponds to real commits on `vlab/<story-id>` in a
  worktree under `.workspace/.worktrees/`.
- The model can modify the checkout and run arbitrary commands there. This is
  the product owner's explicit requirement. It is not an OS sandbox: a malicious
  repository or model command could still reach the host network or read
  accessible files outside the worktree through the shell. Operators must run
  VLab on a machine and account they trust for this activity.
- Paid provider usage grows with rounds and stories; bounds cap each attempt,
  not the number of attempts across starts.
- Worktrees and branches accumulate for auditing. `make clean-workspace`
  removes the workspace; branches live in the project clone.
- Real work needs `git` and the tools used by the repository; failures are
  reported as content-free codes and the story is retried or blocked.

## Alternatives considered

- **Keep the simulation**: rejected by the product owner.
- **Work directly in the main clone**: rejected; concurrent stories need
  isolation and a reviewable branch. Worktrees provide both.
- **Give the model free choice of paths and commands without validation**:
  rejected; path confinement and output bounds stay application-owned.
- **OS-level sandbox (container, seatbelt)**: stronger, but a larger decision
  and not required for the local single-user product stage. Recorded as a
  residual risk.
- **Unbounded autonomous loop**: rejected; bounded rounds, time, output, and
  attempts are mandatory.
