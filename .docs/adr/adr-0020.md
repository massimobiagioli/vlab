# ADR-0020: Interactive agent wizard and laboratory skill policy

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

Specification §7.2 requires a guided procedure to create an agent, with a
summary and confirmation, validation at entry and commit, and atomic
persistence of the profile and memberships. The plan makes two assumptions
blocking for WP-3:

- **A-07**: `--check-lab` requires at least one skill for members with role
  `dev`, `analyst`, or `qa`; the `lead` may have none.
- **A-09**: `--new-agent` requires an interactive terminal; non-interactive
  creation is not supported, and the wizard logic is tested through a prompt
  port.

The product owner confirmed both assumptions on 2026-11-12 before WP-3.

## Decision

1. **Prompt port.** `app::agents::wizard::Prompter` exposes `is_interactive`,
   `ask`, `confirm`, and `show_error`. Production uses a terminal
   implementation; tests use a scripted one. The wizard has no direct terminal
   or process access.
2. **Interactive-only creation.** `--new-agent` checks for a terminal before
   reading settings or opening the database. A non-interactive invocation
   exits 4 with an actionable hint and creates no files or rows.
3. **Question sequence.** Name, role, description, skills, provider (default
   from settings), model (default from settings), optional CV, laboratory
   memberships, summary, confirmation. Empty answers use the shown default.
   Invalid answers are reported and re-asked, with a bounded number of
   attempts (10) before the command aborts.
4. **Validation.** Names are trimmed, 1–100 characters, and single-line.
   Descriptions are trimmed, 1–2000 characters, and single-line. Skills are
   comma-separated slug tags, normalized, deduplicated, at most 20; the
   wizard requires at least one for `dev`, `analyst`, and `qa` (A-07). The CV
   is optional, at most 64 KiB, and NUL-free. Provider and model must parse as
   supported identifiers.
5. **Memberships.** The active laboratory is pre-filled when it still exists;
   otherwise one or more laboratory IDs are required. Additional IDs are
   accepted, deduplicated, and each must exist. A stale active selection is
   ignored rather than defaulted to a missing laboratory.
6. **One Tech Lead.** Before the summary, every target laboratory is checked
   for an existing active `lead`. A second lead aborts with a validation error
   (exit 4) and no write.
7. **Confirmation and persistence.** The summary lists every field except CV
   content. A declined confirmation returns cancellation (exit 5) and writes
   nothing. On acceptance, the profile and all memberships are inserted in one
   transaction; a failure rolls back both.
8. **Provider and model copies.** Values are taken from settings at creation
   time and stored in the profile. Later settings edits do not alter existing
   agents (specification §5.4).
9. **No provider call.** The wizard is local; `--check-lab` and the lists also
   perform no provider I/O. The crate has no HTTP client dependency until
   WP-5; a test asserts this.

## Consequences

- The flow is deterministic, unit-testable, and cannot hang on piped input.
- Users cannot script agent creation in this release (A-09); a future
  non-interactive path needs a new decision and an ADR.
- The wizard is stricter than `--check-lab` for skills on operational roles,
  so a wizard-created laboratory is less likely to fail validation.
- Single-line prompts mean a multi-line CV must be pasted as one line in this
  release; a multi-line editor flow is a possible later improvement and is
  documented as a limitation.
- The bounded re-prompt count prevents an endless loop from a broken terminal.

## Alternatives considered

- **Non-interactive flags for every field**: rejected by A-09; it adds a
  second input contract and more validation surface before the release.
- **Trust the summary and validate only at commit**: rejected; errors would
  surface late and after several answers.
- **Allow a second lead and let `--check-lab` report it**: rejected; the
  specification requires the wizard to reject it before saving.
- **Store memberships after the profile in separate transactions**: rejected;
  a partial agent would violate the atomicity requirement.
- **Send the CV to the provider**: rejected (A-13).
