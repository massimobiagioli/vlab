# ADR-0017: Temporary vendored sqlx-sqlite patch for RUSTSEC-2026-0459

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

WP-2 adds SQLx 0.9.0 as required by [`../STACK.md`](../STACK.md) and
[ADR-0002](adr-0002.md). The SQLite driver, `sqlx-sqlite` 0.9.0, requires
`libsqlite3-sys >=0.30.1, <0.38.0`. Every `libsqlite3-sys` release from 0.6.0
to 0.38.2 bundles an SQLite version affected by CVE-2026-119375
(RUSTSEC-2026-0459, medium): a crafted database and sibling `-wal` pair can
make queries return stale page-cache memory. `cargo audit` and
`cargo deny check` fail on the dependency graph, and `AGENTS.md` §7 forbids
suppressing the finding to pass the gate. The vulnerability is local, but
VLab must not ship a known-vulnerable engine when a fixed one exists.

The fixed `libsqlite3-sys` releases are 0.39.0 (SQLite 3.54.0) and 0.39.1
(SQLite 3.54.1). No published `sqlx` release accepts them: 0.9.0 is the latest
release. Upstream `sqlx` `main` has already widened the requirement to
`<0.40.0`, so the change exists but is not released.

## Decision

1. Vendor the published `sqlx-sqlite` 0.9.0 sources under
   [`../../vendor/sqlx-sqlite`](../../vendor/sqlx-sqlite) and select them with
   `[patch.crates-io]` in the root `Cargo.toml`. The crate name and version
   stay `sqlx-sqlite 0.9.0`.
2. Change exactly one dependency requirement in the vendored manifest:
   `libsqlite3-sys` becomes `>=0.30.1, <0.40.0`. No Rust source, feature,
   license, or public API changes.
3. Pin `libsqlite3-sys` 0.39.1 in `Cargo.lock`. The build bundles SQLite
   3.54.1 through that release.
4. Record provenance, the published crate checksum, the removed non-build
   files, and the exit condition in [`../../vendor/README.md`](../../vendor/README.md).
5. Remove the vendor directory and the `[patch.crates-io]` entry as soon as a
   published `sqlx`/`sqlx-sqlite` release accepts `libsqlite3-sys >=0.39`, then
   rerun every gate. Removing the patch is not a new decision.

## Consequences

- `cargo audit` and `cargo deny check` pass on the actual engine the build
  uses, rather than on a suppressed advisory.
- Builds stay reproducible and offline: the patch is a path dependency with
  pinned sources, not a git dependency. `Cargo.lock` pins the fixed engine.
- The repository carries a temporary copy of one crate (about 0.5 MiB). A
  reviewer must compare it with crates.io when reviewing the change; the
  checksum and the single-line diff are documented.
- While the patch exists, dependency updates must keep `libsqlite3-sys` at
  0.39.x or later (and below 0.40 for this SQLx release).
- If upstream changes the SQLite driver API before this patch is removed, the
  patch is not a viable merge base; the dependency must then be upgraded
  instead.

## Alternatives considered

- **Ignore or allow the advisory in `deny.toml` / `cargo audit`**: rejected;
  `AGENTS.md` §7 and `SECURITY.md` forbid suppressing findings to pass a gate.
- **Switch to `rusqlite` 0.41**: rejected; `STACK.md` mandates SQLx, and a
  database-library change is a much larger architectural change than this
  temporary patch.
- **Link the system SQLite (`unbundled`)**: rejected; the engine would vary by
  host (macOS 26 ships 3.51.0, which is also before 3.54.0), breaking the
  reproducible, verified-engine requirement of `STACK.md`.
- **Use an unreleased git revision of `sqlx`**: rejected; `deny.toml` forbids
  unknown git sources, and a moving revision is less reproducible.
- **Wait for the next SQLx release**: rejected as a way to complete WP-2 now;
  the exit condition records the upgrade path.
- **Disable WAL and argue reduced exposure**: rejected as a gate workaround;
  WAL is already disabled, and the advisory still applies to the library.
