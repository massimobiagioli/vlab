# ADR-0006: Agent guidance, portable skills, and ADR governance

- Status: Superseded
- Date: 2026-11-12
- Supersedes: —
- Superseded by: ADR-0007

## Context

Contributors include humans and multiple AI coding tools. Instructions,
decisions, and reusable procedures must have one version-controlled source and
must not drift between tool-specific copies. The repository tracks `.docs/`
and `.agents/`; local scratch and planning directories are outside version
control and cannot be cited as authoritative sources.

## Decision

1. **Single entry point**: `AGENTS.md` at the repository root is the entry point
   for every human or AI contributor. It links every tracked document under
   `.docs/` and every skill under `.agents/skills/`.
2. **Tracked sources of truth**: project rules, security requirements, stack
   constraints, validation expectations, and architecture decisions live under
   `.docs/`. Local directories outside version control are not sources of
   truth and must not be referenced by tracked guidance.
3. **ADRs**: every material technical decision is recorded in
   `.docs/adr/adr-NNNN.md`, where `NNNN` is the next zero-padded sequence
   number. Each ADR states status, date, context, decision, consequences,
   alternatives, and references.
4. **Registry**: `.docs/adr/registry.md` is the authoritative index. Adding an
   ADR and updating the registry happen in the same change. The registry is
   linked from `AGENTS.md`.
5. **Skills**: reusable procedures live in
   `.agents/skills/<skill-name>/SKILL.md`. Frontmatter contains only `name` and
   `description`, which are understood by both Claude Code and OpenCode. Skill
   bodies are plain Markdown and must not depend on tool-specific features.
6. **No duplication**: do not create parallel `CLAUDE.md`, `.claude/skills`, or
   tool-specific instruction trees that repeat this content. If a tool cannot
   discover `.agents/skills` natively, configure it to load that directory
   rather than copying files.
7. **Language**: all tracked documentation, ADRs, skills, and `AGENTS.md` are
   written in English.

## Consequences

### Positive

- One source of instructions for every tool.
- Portable skills avoid configuration drift.
- ADRs preserve the reasoning behind decisions and make reviews cheaper.
- The registry makes decision history discoverable.

### Negative / trade-offs

- Some tools may require explicit configuration to discover `.agents/skills`.
- ADR discipline adds a small, proportional overhead to material changes.
- A single `AGENTS.md` must stay concise enough to remain useful.

## Alternatives considered

- **Per-tool instruction files**: rejected because they drift and duplicate
  maintenance.
- **ADR content only in commit messages**: rejected because decisions must be
  discoverable without repository archaeology.
- **Skills embedded in `AGENTS.md`**: rejected because procedures would be
  loaded for every task and would make the entry point unwieldy.
- **Tool-specific frontmatter**: rejected in favor of the smallest common
  subset.
