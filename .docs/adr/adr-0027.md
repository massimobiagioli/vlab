# ADR-0027: Allow ISC and CDLA-Permissive-2.0 for the TLS dependency graph

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

The DeepSeek adapter adds `reqwest` with rustls. Its transitive graph includes
`aws-lc-rs`, `aws-lc-sys`, `rustls-webpki`, `untrusted`, and
`webpki-root-certs`, under ISC and CDLA-Permissive-2.0 licenses. The existing
`deny.toml` allowlist does not include them, so `cargo deny check licenses`
fails. `AGENTS.md` §7 forbids ignoring license findings.

## Decision

Explicitly allow `ISC` and `CDLA-Permissive-2.0` in `deny.toml`. Both are
permissive and compatible with the project's MIT OR Apache-2.0 licensing.
Every other license remains denied; no crate is ignored.

## Consequences

- The TLS stack can be used and audited under an explicit policy.
- Future crates under these licenses are permitted; their attribution
  obligations remain with the dependency sources.
- The license gate still rejects copyleft and unknown licenses.
- The dependency register records the new direct dependencies; the transitive
  graph is covered by `cargo deny`.

## Alternatives considered

- **Ignore the crates**: rejected; ignores hide future license changes.
- **Use native-tls instead of rustls**: rejected; platform-specific TLS and
  certificate stores complicate reproducible behavior.
- **Relax the gate to warnings**: rejected by `AGENTS.md` §7.
