# ADR-0013: Local quality gates until Go-Live; hosted CI deferred

- Status: Superseded
- Date: 2026-11-12
- Supersedes: ADR-0012
- Superseded by: ADR-0029

## Context

ADR-0012 enabled GitHub Actions CI, a daily security scan, and Dependabot.
The repository has no remote yet. The product owner wants WP-1 to WP-6
delivered as uninterrupted implementation work, with every hosted,
production, or live-provider activity grouped in a Go-Live phase after WP-6.
`AGENTS.md` §7 already requires the full gate set to pass locally before a
change is complete, so quality is still enforced without hosted CI.

## Decision

1. Keep `.github/workflows/ci.yml`, `.github/workflows/security.yml`, and
   `.github/dependabot.yml` in the repository, fully commented out, with a
   header explaining how to activate them. Their content is the ADR-0012
   configuration, unchanged.
2. Until Go-Live, run the gates from `AGENTS.md` §7 locally before every
   change: `cargo fmt --all -- --check`,
   `cargo clippy --locked --all-targets -- -D warnings`,
   `cargo test --locked`, `cargo audit`, and `cargo deny check`. A change
   whose gates fail locally is not complete.
3. Activate hosted CI, the daily scan, Dependabot, and branch protection in
   the Go-Live phase of `.project/IMPLEMENTATION-PLAN.md`, before the release
   tag. From then on, ADR-0012 points 1–4 and 6 apply again as written.
4. The `deny.toml` policy from ADR-0012 point 5 stays in force now, since
   `cargo deny check` is a local gate.

## Consequences

- No hosted run checks a change before Go-Live. Contributors must run the
  gates themselves, and the evidence lives in package reports.
- Linux is not checked until Go-Live unless a contributor runs the gates on
  Linux.
- Advisories published between changes are only caught by the next local
  `cargo audit`; there is no daily scan before Go-Live.
- Activation needs no redesign: the commented files can be restored
  verbatim.

## Alternatives considered

- **Keep CI active**: rejected; the product owner wants hosted activities
  after WP-6, and there is no remote to run on.
- **Delete the workflow files**: rejected; the reviewed configuration would
  have to be rewritten at Go-Live.
- **Move the files outside `.github/`**: rejected in favor of commenting, as
  requested; the files stay where they will run.
