# ADR-0040: Track the entire .project directory

- Status: Accepted
- Date: 2026-11-13
- Supersedes: —
- Superseded by: —
- Amends: ADR-0007 and ADR-0037 (version-control scope only)

## Context

ADR-0007 tracked only `.project/IMPLEMENTATION-PLAN.md`; ADR-0037 added
`.project/features/*.md` while keeping other `.project/` content as local
scratch. The product owner now requires the whole `.project/` directory to be
versioned so planning notes, feature plans, and related delivery artifacts are
reviewable and portable with the code.

## Decision

1. Track every file under `.project/`; remove the `.project` ignore rules from
   `.gitignore`.
2. Keep `.tmp/`, `.data/`, `.workspace/`, and other local runtime state out of
   version control.
3. `.project/` content must still be safe to commit: no credentials, local
   absolute paths, generated databases, or unreviewed sensitive data.
4. Existing governance for feature plans remains: five-digit filename prefix,
   branch identifier, ordered checkboxes, and completion only when every task is
   checked (ADR-0037).
5. Local scratch that must not be committed belongs under `.tmp/`, not
   `.project/`.

## Consequences

- Planning and feature artifacts are fully reviewable with the code.
- Contributors must review `.project/` changes like any other tracked file.
- Accidental scratch files under `.project/` become visible in `git status`;
  they must be moved to `.tmp/` or removed.
- No runtime behavior changes.

## Alternatives considered

- **Keep selective tracking**: rejected by the product owner; partial tracking
  hides useful planning context.
- **Track only Markdown**: rejected; the requirement is the whole directory.
- **Ignore the whole directory**: rejected; it is the current problem.
