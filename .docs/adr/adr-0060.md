# ADR-0060: Agent definitions from markdown files

- Status: Accepted
- Date: 2026-11-17
- Supersedes: —
- Superseded by: —
- Amends: ADR-0020 (agent validation), ADR-0052 (preset catalog)
- Related: ADR-0059 (file store)

## Context

The product owner wants to create an agent from a source markdown definition:

```sh
make agent-create-from-file SRC=<markdown-file>
```

The definition must be readable and reviewable without a database, while using
the same validation rules as the wizard and the preset catalog. The active
laboratory is the natural membership target, but a file import may run without
an active laboratory.

## Decision

1. **File format.** A definition is UTF-8 markdown with YAML frontmatter:
   ```markdown
   ---
   name: Ada
   role: dev
   description: Backend developer
   skills: [rust, sqlite]
   ---
   # Professional profile
   ...
   ```
   The frontmatter has exactly `name`, `role`, `description`, and `skills`.
   The markdown body is the optional CV/professional profile. The file is
   bounded to 128 KiB.
2. **Validation.** The frontmatter is parsed strictly with `serde-saphyr`;
   unknown fields, malformed YAML, oversized content, and non-UTF-8 input are
   rejected before storage. Name, role, description, skills, and CV use the
   existing domain rules (`PresetAgent::parse`, ADR-0020, ADR-0052). A `lead`
   may have no skills; every other role needs at least one.
3. **Creation.** The command allocates a new agent identifier and copies
   provider and model from the current settings. It inserts the profile
   atomically. If the active laboratory exists and is valid, the agent joins
   it; a second lead is rejected. Without a usable active laboratory, the
   profile is created without membership and remains available to Populate.
4. **No overwrite.** The command always creates a new profile. It does not
   update an agent with the same name; duplicate names remain allowed as in the
   wizard.
5. **Audit and memory.** The dispatch records one `agent_created` event and the
   automatic structural agent memory, using the file-backed memory store when
   available.
6. **Interface.** The hidden CLI action
   `vlab --create-agent-from-file <file>` is wrapped by
   `make agent-create-from-file SRC=<file>`. The path is read from the current
   working directory or an absolute path.
7. **Tests.** Parser tests cover valid definitions, missing/unknown fields,
   invalid roles and skills, body/CV, size, UTF-8, and markdown extension.
   Application tests cover membership, lead conflict, no active lab, and the
   new profile fields. A CLI test covers the Makefile-facing command.

## Consequences

- Agent definitions are versionable, reviewable files.
- The active laboratory is used when available; otherwise the import produces
  a reusable catalog profile.
- The command does not call the provider and never executes markdown content.
- The body is stored as the agent CV; it is not sent to a provider except
  through the existing bounded planning/question paths if a caller deliberately
  includes it.
- A definition file is not copied into the documents store; it is an input
  artifact, not project documentation.

## Alternatives considered

- **Use the YAML preset catalog for one agent**: rejected; the product owner
  asked for a markdown source and a per-agent command.
- **Parse headings instead of frontmatter**: rejected; it is ambiguous and
  harder to validate strictly.
- **Require an active laboratory**: rejected; importing into the catalog is
  useful without context.
- **Overwrite an existing agent by name**: rejected; silent profile mutation is
  surprising.
- **Store the source file as a document**: rejected; the definition is input,
  while the CV is already part of the profile.
