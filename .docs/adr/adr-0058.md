# ADR-0058: Agent duplication with optional memory preservation

- Status: Accepted
- Date: 2026-11-17
- Supersedes: —
- Superseded by: —
- Amends: ADR-0020 (agent validation), ADR-0036 (automatic memory)
- Related: ADR-0022 (scoped memories), ADR-0053 (populate screen)

## Context

The product owner wants a **duplicate** function for agents, with an option to
**preserve memory**. Duplicating an agent is useful as a template: an operator
can copy a profile with its role, description, skills, CV, provider, and model,
then adapt it without retyping every field.

An agent has one global profile and several laboratory memberships. Agent-scope
memories are stored separately and have their own bounds (20 memories, 2,000
characters each, credential rejection). The one-Tech-Lead rule means a duplicate
of a lead cannot join a laboratory that already has that lead.

## Decision

1. **Profile copy.** A duplicate receives a new agent identifier and a
   user-provided name. Role, description, skills, provider, model, and CV are
   copied from the source. The duplicate is always active, even when the source
   is archived.
2. **Membership copy.** The source memberships are copied only where the
   one-Tech-Lead rule allows the new profile to join. A duplicated lead therefore
   gets no memberships; it remains a reusable catalog profile that can be
   populated into a laboratory without a lead. The result reports how many
   memberships were copied or skipped.
3. **Optional memory preservation.** The duplicate form has a `Preserve memory`
   choice (`No` by default, or `Yes`). When `Yes`, every agent-scope memory of
   the source is copied with a new identifier into the duplicate's scope. The
   existing 20-memory and 2,000-character limits apply. Content containing the
   current provider credential is rejected before any write. Memories are
   copied in their stored order; their creation time becomes the duplication
   time.
4. **Atomic persistence.** Profile, allowed memberships, and copied memories are
   inserted in one database transaction through a new `AgentCopyStore` port. A
   failure writes nothing.
5. **Dashboard action.** The Agents dashboard gains `c` **Duplicate**. It opens a
   form with the new name and the preserve-memory choice; the name defaults to
   `<source name> copy`. The result reports the new identifier, copied
   memberships, skipped memberships, and copied memory count.
6. **No CLI flag.** Duplication is an interactive profile operation like
   `--new-agent`; a scripted path needs a separate decision.
7. **Audit.** One `agent_created` event identifies the new profile. Copied
   memories are not individually audited because they are a bounded part of the
   same duplication operation and contain no new content.
8. **Tests.** Application tests cover profile fields, new identifier, membership
   filtering, memory copy, the cap, credential rejection, and atomic failure.
   Database tests cover the transaction and copied rows. A dashboard test opens
   the duplicate form, preserves memory, and verifies the new profile and
   memories.

## Consequences

- Operators can reuse a profile without re-entering every field.
- Duplicated leads are not silently added to a laboratory; the result explains
  why, and the Populate screen remains the path to assign them.
- Memory preservation is explicit and bounded; it cannot bypass the memory
  limits or the credential rule.
- Copied memories are independent rows: later edits or deletion of one scope do
  not affect the other.
- The source profile and its memories are never modified.

## Alternatives considered

- **Always copy memberships**: rejected; a duplicated lead would violate the
  one-Tech-Lead rule.
- **Never copy memberships**: rejected; duplicating a non-lead would be less
  useful than it can be.
- **Copy memories by default**: rejected; memory context can be sensitive and
  should be an explicit choice.
- **Reuse the source memory identifiers**: rejected; identifiers are primary
  keys and duplicate rows must be independent.
- **Add a CLI command**: deferred; the existing agent creation path is
  interactive because it needs a terminal.
