# ADR-0021: Width-aware aligned tables with stacked fallback

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —
- Amended by: ADR-0038 (dashboard layout)

## Context

ADR-0005 fixes deterministic rendering without color and requires
sanitization of untrusted text. Specification §10 requires readable output on
narrow terminals, and WP-3-T9 requires aligned columns, an explicit ellipsis
for long cells, a stacked `label: value` fallback below a configured
threshold, empty-state helpers, and no ANSI bytes. `STACK.md` defers
`terminal_size` and `unicode-width` to their first use, which is this package.

## Decision

1. **Width source.** `cli::render::terminal_width()` reads
   `terminal_size::terminal_size()` and falls back to 100 columns when the
   stream is not a terminal or reports an unusable width. Rendering functions
   take the width as a parameter so tests are deterministic.
2. **Display width.** Cell widths use `unicode-width` so wide characters align
   correctly. Every cell is sanitized first; newlines inside a cell become
   spaces, and all other control characters are removed.
3. **Layout.** Columns declare `Identifier` or `Text`. Identifiers keep their
   natural width and are never truncated. If the natural table exceeds the
   terminal, text columns shrink from the widest down to a readable floor
   (`max(8, header width)`) and are cut with `…`. If the table still does not
   fit, output falls back to one `label: value` block per row, with a blank
   line between rows.
4. **No color and no escape output.** No ANSI sequences are emitted; `NO_COLOR`
   is trivially satisfied. Tests assert on raw bytes at widths 40, 80, and
   120 and with control-character cells.
5. **Empty states.** `empty_state(message, hint)` prints an action-oriented
   line pair; list commands use it instead of an empty table.
6. **Dependencies.** Add `terminal_size` 0.4.4 and `unicode-width` 0.2.3
   (MIT OR Apache-2.0) and record them in
   [`../DEPENDENCIES.md`](../DEPENDENCIES.md).

## Consequences

- Tables are readable on wide and narrow terminals without a TUI dependency.
- Identifiers remain copy-pasteable, which matters because every command takes
  them as operands.
- Long names and descriptions are shortened in table mode; detail views show
  the full sanitized value.
- The default width of 100 keeps redirected output stable and reviewable.
- Alignment depends on Unicode display width, not byte length.

## Alternatives considered

- **Fixed-width layout with horizontal scrolling**: rejected; terminals do not
  scroll horizontally in a useful way for this CLI.
- **Truncate identifiers like other cells**: rejected; truncated IDs cannot be
  used as operands.
- **Always stack**: rejected; aligned tables are easier to scan when they fit.
- **Read `COLUMNS` from the environment instead of `terminal_size`**: rejected;
  `COLUMNS` is not reliably exported and can be stale.
- **Add a full TUI framework**: rejected by `STACK.md`.
