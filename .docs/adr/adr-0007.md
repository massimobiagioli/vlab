# ADR-0007: Tracked implementation plan in agent guidance

- Status: Accepted
- Date: 2026-11-12
- Supersedes: ADR-0006
- Superseded by: —
- Amended by: ADR-0037 (tracked feature plans only)
- Amended by: ADR-0040 (tracked .project scope)

## Context

ADR-0006 established `AGENTS.md` as the single entry point, `.docs/` as the
tracked source of truth, and treated local scratch and planning directories,
including `.project/`, as outside version control. The implementation plan in
`.project/IMPLEMENTATION-PLAN.md` sequences the initial release into working
packages and gates. Contributors and agents need a stable, reviewable copy of
that plan to execute work in order, so it must be versioned and linked from the
entry point instead of living in an untracked directory.

## Decision

1. **Single entry point**: `AGENTS.md` at the repository root is the entry point
   for every human or AI contributor. It links every tracked document under
   `.docs/`, every skill under `.agents/skills/`, and the implementation plan.
2. **Tracked sources of truth**: project rules, security requirements, stack
   constraints, validation expectations, and architecture decisions live under
   `.docs/`. Local directories outside version control are not sources of
   truth and must not be referenced by tracked guidance.
3. **Implementation plan**: `.project/IMPLEMENTATION-PLAN.md` is tracked in
   version control and linked from `AGENTS.md`. It defines the order of work
   packages, tasks, and gates. It ranks below every document in `.docs/`; it
   must not introduce rules, technology choices, or decisions that are not
   already recorded there or in an accepted ADR. When it conflicts with a
   higher-ranked document, the higher-ranked document wins and the plan is
   corrected. Other files under `.project/` remain untracked unless a later ADR
   says otherwise.
4. **ADRs**: every material technical decision is recorded in
   `.docs/adr/adr-NNNN.md`, where `NNNN` is the next zero-padded sequence
   number. Each ADR states status, date, context, decision, consequences,
   alternatives, and references.
5. **Registry**: `.docs/adr/registry.md` is the authoritative index. Adding an
   ADR and updating the registry happen in the same change. The registry is
   linked from `AGENTS.md`.
6. **Skills**: reusable procedures live in
   `.agents/skills/<skill-name>/SKILL.md`. Frontmatter contains only `name` and
   `description`, which are understood by both Claude Code and OpenCode. Skill
   bodies are plain Markdown and must not depend on tool-specific features.
7. **No duplication**: do not create parallel `CLAUDE.md`, `.claude/skills`, or
   tool-specific instruction trees that repeat this content. If a tool cannot
   discover `.agents/skills` natively, configure it to load that directory
   rather than copying files.
8. **Language**: all tracked documentation, ADRs, skills, the implementation
   plan, and `AGENTS.md` are written in English.

## Consequences

### Positive

- The plan is versioned, reviewable, and discoverable from the entry point.
- Plan progress and revisions become visible in history.
- All other ADR-0006 guarantees are preserved.

### Negative / trade-offs

- The plan must be kept consistent with `.docs/` and the ADRs; drift is now a
  tracked defect rather than a local concern.
- The plan currently cites untracked `.tmp/` inputs; those citations must be
  removed or the inputs promoted into tracked documentation.

## Alternatives considered

- **Keep the plan untracked**: rejected because contributors need a shared,
  versioned execution order.
- **Move the plan into `.docs/`**: rejected for now to keep the existing path
  and separate execution planning from normative documentation.
- **Track all of `.project/`**: rejected because only the plan is needed and
  scratch content must stay out of version control.
