# ADR-0005: Deterministic terminal rendering without color

- Status: Accepted
- Date: 2026-11-12
- Supersedes: —
- Superseded by: —

## Context

The interface is line-oriented and must remain understandable when output is
redirected, when the terminal is narrow, and when color is disabled. It must
also resist terminal-control injection from stored names and model output.
`STACK.md` requires results on stdout, diagnostics on stderr, stable exit codes,
predictable output when redirected, and no unnecessary TUI framework.

## Decision

1. Render human-readable results to stdout and all diagnostics, warnings, and
   progress information to stderr.
2. Do not emit ANSI color or cursor-control sequences in the initial release.
   `NO_COLOR` is therefore always honored without conditional logic.
3. Make terminal width an explicit renderer input. Production resolves it from
   the terminal or `COLUMNS`, defaulting to 80 columns when output is not a
   terminal. Tests pass fixed widths.
4. Use aligned columns when width permits and fall back to vertically stacked
   `label: value` sections on narrow terminals.
5. Truncate long cells with an explicit ellipsis. Never truncate identifiers or
   exit-code-relevant values silently.
6. Sanitize untrusted text before rendering: remove or replace C0/C1 control
   characters (except newlines) and strip escape sequences.
7. Provide explicit empty states with a next useful action.
8. Do not add a table-rendering, color, or TUI framework unless a later ADR
   demonstrates that the small built-in renderer is insufficient.

## Consequences

### Positive

- Output is scriptable, diffable, and safe to capture in logs.
- Tests are stable across environments because width is injected.
- No dependency on terminal capability detection beyond width.

### Negative / trade-offs

- Less visual hierarchy than color or a TUI can provide.
- Manual alignment logic must be maintained and tested.
- Unicode width handling requires care for wide characters.

## Alternatives considered

- **Color output with `NO_COLOR`**: rejected for the initial scope as visual
  complexity without a demonstrated need.
- **Full-screen TUI**: rejected by `STACK.md`.
- **Third-party table crate**: deferred; the required formatting is modest and
  a small renderer keeps behavior explicit.
