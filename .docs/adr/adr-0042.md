# ADR-0042: Reusable form modal for dashboard editing

- Status: Accepted
- Date: 2026-11-13
- Supersedes: —
- Superseded by: —
- Amends: ADR-0038 (dashboard interaction only)
- Amended by: ADR-0043 (project edit form)

## Context

The first dashboard implementation rendered editable values as inline
`Label: value` text. The product owner found it unclear and not user-friendly:
there was no visible field boundary or cursor, and focus was only explained in a
hint line.

## Decision

1. Introduce one reusable form state for dashboard editing. A form has a kind,
   ordered fields, and a focused field.
2. Each field has a label, value, and character cursor. Insert, Backspace,
   Delete, Left/Right, Home, and End edit the focused field.
3. `Tab`/`Down` and `Shift-Tab`/`Up` move focus; `Enter` saves; `Esc` cancels.
4. Render each field as a bordered input box with its label in the border. The
   focused field uses the accent border and shows a visible cursor; unfocused
   fields are muted.
5. Laboratory new/edit uses fields Name and Description. Project new uses Name
   and GitHub source. Validation and persistence remain in the existing
   application use cases.
6. Error feedback replaces the form with the existing error modal; no field
   value is echoed in validation messages.

## Consequences

- Editing is visible and keyboard-complete without external documentation.
- The same component covers every current dashboard form and future simple
  fields.
- Multi-line editing, clipboard shortcuts, and mouse selection remain out of
  scope.
- Terminal form rendering is tested through `TestBackend` and PTY flows.

## Alternatives considered

- **Keep inline text**: rejected by the product owner; no affordance or cursor.
- **One-line prompt at the bottom**: rejected; it hides context and does not
  scale to two fields.
- **Add a full editor widget dependency**: deferred; the current forms are
  single-line and a small state machine is sufficient.
