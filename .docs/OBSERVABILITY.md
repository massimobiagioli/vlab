# Observability

Diagnostics and audit events, as decided in [ADR-0011](adr/adr-0011.md) and
constrained by [`SECURITY.md`](SECURITY.md) (Logging and Audit).

## Diagnostics

- Written to stderr only, through `tracing`.
- Off unless `RUST_LOG` is set, for example `RUST_LOG=debug vlab --list-labs`.
  An invalid `RUST_LOG` prints one warning and leaves diagnostics off.
- Never contain ANSI sequences.
- Every invocation opens a `run` span with a random `run_id`.
- Panics print no payload. With `RUST_BACKTRACE` set (and not `0`), the panic
  location and a backtrace are printed to stderr.

## Audit events

Audit events use the typed API in `src/obs/events.rs`. It has no free-text
field, so request text, prompts, responses, CVs, and credentials cannot be
recorded.

| Field | Type | Notes |
|---|---|---|
| `run_id` | random 128-bit hex | One per process invocation. |
| `action_id` | random 128-bit hex | One per discrete operation. |
| `kind` | `EventKind` | See below. |
| `outcome` | `success`, `failure`, `cancelled`, `denied` | |
| `entity_type`, `entity_id` | `EntityType` (laboratory, agent, project, request, story, memory), 8 lowercase hex | Rejected unless well-formed (ADR-0004). |
| `error_code` | static code | For example `AppError::code()`; never a message. |
| `duration_ms`, `attempt` | integers | |
| `provider`, `model` | `deepseek`, `[A-Za-z0-9._:-]{1,64}` | |
| `schema_from`, `schema_to` | integers | Set only by `migration_applied`. |
| `created_at` | RFC 3339 UTC | Generated by SQLite when the event is stored. |

Event kinds: `migration_applied`, `lab_created`, `lab_updated`, `lab_opened`, `lab_deleted`,
`agent_created`, `agent_archived`, `project_created`, `project_updated`, `project_deleted`,
`request_accepted`, `planning_started`, `planning_completed`,
`planning_failed`, `provider_attempt`, `question_answered`, `confirmation_granted`, `confirmation_declined`,
`budget_exhausted`, `cancelled`, `memory_created`, `memory_deleted`.

Memory events carry only the memory entity identifier; the scope is looked up
from storage when needed. They never carry memory content.

Sinks:

- `TracingSink` emits events as `vlab::audit` diagnostics.
- `MemorySink` keeps events in memory for tests.
- `infra::db::Database` stores events in the `events` table with a
  `created_at` generated by SQLite in UTC (ADR-0016). Failure to persist an
  event is logged as a warning and never turns a completed command into a
  failure.

## Redaction

Secrets travel inside `obs::Redacted<T>`, whose `Display` and `Debug` both
print `[REDACTED]`. `AppError::Io` keeps only the `io::ErrorKind`, because the
underlying message may embed paths or data. `tests/redaction.rs` runs the
binary with the synthetic key `sk-vlab-SECRET-MARKER` in the private
`settings.yaml` and `RUST_LOG=trace`, and asserts that the marker never appears
on stdout or stderr.
